mcpit: any website, as an MCP server

The first visit to a site is slow: mcpit explores it and saves a sitepack of forms, search and API endpoints. Every later visit uses the sitepack and is fast. Shared sitepacks let other users skip the slow visit.

Core idea

The lookup ladder

For each call, mcpit takes the first rung that works. Select a case to see the path.

Targets 1–5

Components

One TypeScript monorepo. One core library; four front ends; one public registry.

MCP toolUse
mcpit_findFind site tools by URL, domain or task text.
mcpit_toolsList the tools of one site, loaded on demand to keep the agent context small.
mcpit_callCall one site tool. Write tools ask the user first (MCP elicitation).
mcpit_exploreExplore a URL now (slow path). Streams progress.
mcpit_readRead main text or tables while exploration runs.
mcpit_reportReport a broken or wrong tool.
mcpit_publishPublish a local sitepack. Shows a diff; the user approves.
Targets 7, 11, 12

Exploration and the decision engine

Exploration makes many small decisions. The engine asks the cheapest source first and stops when confidence is high enough. jev is optional.

How mcpit uses jev

  • Self-contained statement pairs: "A form with fields [q, category] is / is not a site search".
  • Score each option on its own (independent mode). Native multi-choice is biased by option order.
  • jev tends to say "true". It ranks and breaks ties. It never gives a final "safe" verdict alone.
  • Every decision is stored and shown ("how jev helped"), and measured against the LLM.
  • No jev installed: the engine goes from rules straight to the LLM.

CLI in idle time (target 11)

  • mcpit history import reads origins and visit counts only.
  • It drops banking, health, mail, intranet and private IPs by default.
  • The user reviews the queue before the first batch.
  • mcpit batch --idle --budget 2h runs one site at a time, inside a token and memory budget, and stops when the user comes back.
Targets 4, 6, 8

Share structure, never data

In a sitepack

  • Endpoint URL templates and methods
  • Parameter names, types, enums, defaults
  • Selectors and multi-step flows
  • Output shape (JSON paths)
  • Effect class: read · write · payment · destructive
  • Anonymous counters (site, tool, ok/fail)

Never leaves the machine

  • Cookies, auth headers, tokens, keys
  • Values the user typed; response bodies
  • IDs and emails in paths (/user/1234 → /user/{id})
  • Full URLs with query values; history
  • Anything from localhost, private IPs, intranet

Target 13

Edge cases beyond security and validation

Site behavior

  • Site changes: fingerprint per pack, re-explore only the broken tool, cut off tools with low success rate.
  • Dynamic tokens (CSRF, nonce, JS-signed params): token step, or browser-only executor.
  • Multi-step flows, pagination, cursors, infinite scroll.
  • SPA routes, GraphQL persisted queries, WebSocket, SSE, gRPC-web.
  • Iframes, shadow DOM, cross-origin widgets.
  • Locale, region, A/B and mobile variants.
  • Rate limits: back off, honor Retry-After, no IP rotation.
  • CAPTCHA and bot checks: stop and hand to the user. Never bypass.

Actions and agents

  • Write, payment, destructive tools: never probed; always confirmed; dry-run if the site has one.
  • Show filled parameters before any write call.
  • Page text is untrusted: may hold prompt injection.
  • Too many tools: on-demand loading and search.
  • Slow first visit: stream progress; use mcpit_read meanwhile.
  • Cost: token budget per site and per day.
  • One action per tab; limit parallel explores; obey the 80 % memory cap.

Registry and community

  • Fake popularity: account-weighted votes, capped counters.
  • Site owners: claim by DNS TXT or /.well-known/mcpit.json; owner pack wins; opt-out.
  • robots.txt, polite crawler, takedown process for ToS issues.
  • Registry outage: local cache; registry is never on the hot path.
  • Schema versions and migrations.
  • Delete my data: one command locally; account wipe in the registry.
  • Shared machines: store per OS user; no incognito.
