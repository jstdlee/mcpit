mcpit: any website, as an MCP server

The first visit to a site is slow: mcpit explores it and saves a sitepack. Later visits are fast. The registry decides which shared sitepack version is good, so every user gets the best one.

Changes from v2
  • The Chrome extension is out of scope for now: users may not trust it, and it explores APIs and forms poorly. It moves to legacy/extension/.
  • The scope is the MCP server, the CLI and, most important, the registry.
  • Sites behind a login use mcpit login: a visible browser opens once, with an mcpit-only profile. Later runs use it headless, and cookies stay local.
  • The registry owns versions, validation, repeated submits, update decisions, the screening gate (rules + Clef) and the service settings.

Registry

Is the new submit a real improvement?

The screener classifies each changed tool. Promotion is per tool: a fix to one tool never replaces the other tools.

ClassSignalDecision
ConfirmationSame as active+1 agreement
CorrectionActive probe fails or has failure reports; candidate passespromote tool
Drift updateSite fingerprint changed; candidate matches the new sitepromote tool
ExtensionNew read tools; existing tools unchanged and passpromote new tools
CosmeticOnly description or names differpromote if Clef/LLM say it fits better
AlternativeBoth pass; other endpoint or flowkeep; agreement and success decide
RegressionRemoves passing tools, a probe fails, worse outputreject
RiskyWider effect, new domain, new auth, new write toolquarantine
score = 0.35·replay_pass + 0.20·agreement + 0.15·field_success_rate + 0.10·clef_score + 0.10·llm_score + 0.10·submitter_reputation

Registry · service management

Registry settings console

Roles: admin, moderator, site owner, contributor, screener. Every action goes to the audit log.

Sources

Sites and their pack sources: community, owner-claimed, native, crawler. Trust per source. Domain allow and deny lists.

Mark good / bad

Verified badge, or blocked so clients refuse it. A moderator verdict overrides the score.

Expire days

Global default 60 days and per-site override. The screener re-verifies before expiry; clients warn after.

Sort and rank

By use (calls, unique clients), stars, trust, trend, newest. One star per account per site.

De-list / re-list

Hide a site or version from search and pulls, with a reason: takedown, owner opt-out, abuse, legal.

Owner claim

DNS TXT or /.well-known/mcpit.json. Owner packs rank first; owners can opt out.

Screening

Clef-flash/Clef thresholds, BYOK LLM key and model, external screener tokens, daily budget, required agreement, auto-promote limits per class.

Device keys

No accounts. Each new key waits for review: fingerprint, first submit preview, AI assistant note. Approve, reject, revoke.

Quarantine queue

Diff view, replay results, Clef and LLM reasons. Approve or reject.

Gate · models

Screening agent and models

The gate is a screening agent built with the Cloudflare Agents SDK: one Durable Object per site, with its own SQLite, queue and schedules. The owner is the only moderator; the agent prepares every decision for one-click review.

Model test · 2026-10-04

Clef vs DeepSeek on 12 screening cases

23 checks with known answers: search and login forms, wrong descriptions, a write tool labelled read, data sent off-site, prompt injection, a fix, a cosmetic change, a regression, site drift, a new payment tool and a new read tool. 3 runs each, REST from the GB10 (latency includes network).

ModelCorrectMedianp90Note
clef-flash21/23574 ms976 msClass "risky" right (0.83), but "needs human" only 0.26.
clef21/23696 ms1576 msBest calibrated: 0.94–0.99 on clear cases.
deepseek-v4-flash22/232573 ms3819 msNeeds a prompt and JSON parsing; about 4× slower.

All three called site drift a "correction". Rules see drift from the fingerprint, so no model needs to decide it. Workers AI has no DeepSeek V4.1 Flash; v4-flash-0731 is the newest Flash there.
